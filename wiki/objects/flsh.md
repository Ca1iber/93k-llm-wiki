## 是什么

**`FLSH` 是让「被缓冲的 utility line 命令」生效的那条命令。**

本篇开头两句（逐字）：

> 「The following commands for utility lines do not immediately set the hardware. Instead they are
> buffered in the MCD (Message Concentrator and Distributor).」

**被缓冲的是四条命令**，原文列成一张带链接的清单：

| 命令 | 原文给的展开 |
|---|---|
| `UPST` | `Utility Purpose STate` |
| `UPTI` | `Utility Purpose settling TIme` |
| `UTST` | `UTility line STate` |
| `UTTI` | `UTility line settling TIme` |

**展开里的大小写混排（`UTility`、`TIme`）是原文如此**，不是转换坏的——
和本篇标题的 `FLuSH` 是同一种写法。

### 这一篇没有一句话说 `FLSH` 自己干什么

**原文讲了「什么被缓冲」，但通篇没有一句以 `FLSH` 为主语的说明。**
整篇能读到的只有两处：标题的展开 `FLSH - (FLuSH buffered commands)`，和语法行本身。
那四条命令的存在**暗示**了作用，**但本篇不写这句话。**

**补上这句话的是别人家的文档**——`WSDN` 那篇说它触发下载，`FTCG` 那篇的一条消息说它会关时钟
（**两条都不是本篇写的**，见 `## 典型用法` ⑤）。

## 典型用法

**① 语法：`FLSH {MUX}, {"init_flags"}`——两个参数，参数表只讲了一个。**

**`init_flags` 在整份语料里只出现这一次**，就在这一行里：
没有取值说明、没有一个例子、没有别篇提到它。**本页对它一个字都写不出来。**

**② `MUX` 是「可选的」，但语法行没把它写成可选的样子。**

参数表逐字：

> 「The optional MUX parameter is designed to be used as an execution code of a testflow
> that is generated by the system software for disconnecting the particular sites (not for user programming).」

紧接着那句是给读者的禁令：

> 「Do not use this parameter for programming a user procedure or executing the FLSH command from the hpt.」

**合起来读：这个参数是给「系统生成的 testflow」当执行码用的，用户不该写它。**
**可语法行写的是 `{MUX}`（必填的样子），不是 `[{MUX}]`。**
（对照：它的搭档 `WSDN` 语法行就是一个光秃秃的 `WSDN`。）

**③ 省略与不省略，语料里都有实例。**

- **不写参数**：`02.06.02.02.304_UPAS` 的多 site 例子写的是光秃秃的 `FLSH`。
  （**引自 [[pin]] 页的转述；那页记了完整例子，本页没读 `UPAS` 那篇 raw。**）
- **写 `MUX`**：[[smartcalc-framework]] / [[smartcalc]] 两页里那段生成的代码写的是
  `FLSH MUX;WSDN;…`——**这正是参数表说的「系统软件生成的 testflow」的实际样子。**
  （**引自那两页；两页的 raw 本页都没读。**）

**④ 光发 `FLSH` 不够的情形：utility purpose 要先 `UPST` 选中。**

[[pin]] 页记下的一条（来源是 `02.06.03.01.08` 的 Note、`02.06.12.01` 复述）：
`DFUP` 设的标准状态**只发 `FLSH` 不够**，必须**先用 `UPST` 选中、再 `FLSH`** 才真正下载到硬件。
（**这一条转引自 [[pin]] 页；那两篇 raw 本页没读。**）

**⑤ 别家文档给 `FLSH` 补上的两件事**（**两条都不是本篇写的**）。

**这里只做转述、不作逐字引文**：本页 `sources:` 只声明了 `FLSH` 本篇，
**把别篇的整句原文搬过来，那句子在本页就没有可核对的归属**
（本工程的自检工具正是按「引文必须能在本页 sources 里找到」这一条判的）。

| 补的是什么 | 出自 | 那一篇怎么说（转述） |
|---|---|---|
| **刷哪些东西** | `WSDN` 那篇开头 | `WSDN` 等的是**由 `FLSH` 触发的下载**完成；下载对象是 `readiness analog set`（就绪模拟集）的设置，以及 `routing settings`（路由设置） |
| **代价是什么** | `FTCG` 那篇的一条消息 | 消息里说 `Flush` 这条命令**会强制关掉时钟**（`forces a clock off`），结果是**所有通道停止** |

**第一句补的是「刷什么」，第二句补的是「代价」。本篇两件都没写。**

后果是：**`FLSH` 的本篇文档读起来只像一个关于 utility line 的小命令**，
而它实际上会关时钟、因而会停掉所有通道——
**这正是 7.1.4 那条 Functional change 的背景**（见 `## 版本`）。

**⑥ `WSDN` 是常配的下一句。** 两篇的关系是双向的：
`WSDN` 那篇的语法与例子就是把两条连着写（先 `FLSH`、再 `WSDN`），
而且那篇还说：**如果 `FLSH` 的 setup 序列没在跑，`WSDN` 不起作用、立刻返回**（**转述**）。

**⑦ L2 那一层不直接发它。** Test Method 侧调 [[flush]]，由它的 `force` 参数决定要不要发
`FLSH` + `WSDN`，**默认发**。（**引自 [[flush]] 页；那页本页没读。**）
