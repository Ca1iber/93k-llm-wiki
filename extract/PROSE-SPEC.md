## 硬规矩（违反了这页就得重写）

1. **`## 语法 / 参数` 一节一个字都不许改。**
   它在 `<!-- 语法节 begin … -->` 和 `<!-- 语法节 end -->` 之间。
   你的 Edit 的 `old_string` **不要跨进这个区间**。

2. **frontmatter 里这几个键原样留着，不许动**：
   `type` / `title` / `layer` / `stage` / `sources` / `created` / `verified`。
   要改的只有：`tags`（填）、`related`（填）、`updated`（改成今天 `2026-09-18`）。

3. **删掉骨架那段注释**：
   ```
   <!-- 骨架由 `extract/objscaffold.py` 生成。
        「语法 / 参数」节是脚本逐字抽的（§4），**不许改**；
        其余 `（待补）` 由 LLM 补完，补完请删掉本注释。 -->
   ```

4. **`[[wikilink]]` 只许写 allowlist 里的名字。**
   清单：`extract/prose-allowlist.txt`（一行一个）。
   **清单外的一律用反引号写名字**：`` `Trend chart view` `` （要写 raw 路径就连着写）。
   理由（§9.1）：链一个清单外的名字 = 造一个**永远不会建的悬空目标**，
   那会给第八类灌水，把工作单变成噪声。**这一条是本工程最容易犯、后果最脏的错。**

5. **每个事实都要能在你读的文档里找到。**
   - **文档没写** → 写「**语料未写**」，不许推测填空。
   - **你的推断** → 必须显式标「（推断）」并给出推断依据（按 §11 的三分：文档事实 / 推断 / 建议）。
   - **不许**把别处文档的内容写进本页正文。**只写你读的那几篇里有的。**

6. **`## 出处` 必须写「本页没做的」**：哪些相关文档没读、哪些图没看、
   哪些节没展开。**这一节是这一页的可信度声明**，不是客套。
   看完 exemplar 就懂这份声明的密度。

7. **语料的瑕疵照实记，一处都不许替它改。**
   错别字、自相矛盾、链接指错、大小写不一致——在 `## 出处` 里 `⚠️` 列出并**逐字引**。
   **§11.2 明令：不许替语料改，也不许假装没看见。**

## 文风

**先读这两页，照着写**（它们已经建好了，是本 wiki 的定稿风格）：

- `wiki/objects/analysis-views.md`
- `wiki/objects/xps256-status-flags.md`

要点：

- 短句、中文。**关键判断加粗**。
- 能列成表的就列表。**「条件 → 结果」这类内容表格化**。
- 不写「本文将介绍…」这类填充句。**第一句就是实质。**
- 原文的关键句**逐字引**（用 `>` 引用块），并给英文原文。
- 一节写不下了就自己起 `###` 子节。**不许为了整齐删掉内容。**

## 一节该写什么

| 节 | 写什么 |
|---|---|
| `## 是什么` | 这东西**是什么**、干什么用、关键机制。**占本页一半以上篇幅。** |
| `## 典型用法` | 怎么用。步骤、顺序、常见组合。文档里有 `## Procedure` / `## Before you begin` 就读它 |
| `## 和谁有关` | 和别的页的关系。每条说清**是什么关系**（前置/同类/上游下游），不只是列名字 |
| `## 版本` | 该文档 `## Functional changes` 段里的条目。**没有就写「本文档没有 `## Functional changes` 段」**（这是事实，不是缺陷） |
| `## 出处` | `sources:` 的几篇 + **本页没做的** + 语料瑕疵 |
