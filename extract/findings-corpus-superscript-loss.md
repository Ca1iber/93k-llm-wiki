# 语料损坏：**151 处**上标在 HTML→markdown 转换时被拍平，全变成错误的数

发现时间：2026-09-22
发现方式：**人先发现的**（`2^48` → `248`），然后脚本精确对账 HTML 与 markdown 把范围查全。
归属：**(c) 语料本身如此 → 记录**。**但 2026-09-22 起，这一类被单独立为「A 类」，可以改**
（见 `schema.md` §1.2）。**2026-09-22 当日经人批准、已全部修完**——
语料 **151 处 / 60 篇**、wiki **91 处 / 5 页**，逐字节验过。处置与账目见 **§八** 与 **§十**。
**`tdc-html/raw/` 的 HTML 一个字没动。**

---

## 一、逐字证据

`EMAP`（`02.06.02.02.103`，源 HTML `98590.htm`）：

```
HTML      : The range for this parameter is 0 to2<sup>48</sup> - 1.
markdown  : The range for this parameter is 0 to248 - 1.
```

`GETV`（`02.06.02.02.135`）：

```
HTML      : ... must be in the range 0 to 2147483648 (2<sup>31</sup>).
markdown  : ... must be in the range 0 to 2147483648 (231).
```

> ⚠️ **两个缺陷叠在一起，别记成一件。**
> HTML 源里**本来就是 `0 to2`，没有空格**——`to248` 里丢的那个空格**不是转换丢的**。
> 转换只干了第二件事：把 `<sup>48</sup>` 拍平成 `48`。

## 二、精确范围（脚本对账，不是抽样）

对 `tdc-html/raw/` 全部 9,351 个 htm/html 与 9,393 篇 markdown 逐篇对照：

| 项 | 数 |
|---|---|
| HTML 里 `<sup>` 总数 | **1,720**（376 个文件） |
| 其中「**内容纯数字 + 前面紧贴数字**」 | **151 处**（**60 个文件**） |
| 这 151 处**被拍平成粘连字面量**的 | **151 / 151 = 100%** |
| 受影响 markdown 文档 | **60 篇** |
| 找不到对应 markdown 的 | **0**（映射完整） |

**指数取值——全是 2 的幂和 10 的幂：**

```
2^48  ×70    2^31  ×18    2^21  ×14    2^32   ×7    2^12  ×7
2^7   ×5     2^24  ×4     2^18  ×4     2^5    ×4    2^3   ×3
2^16  ×3     2^2   ×2     2^19  ×2     2^15   ×1    2^23  ×1    2^28  ×1
10^18 ×2     10^7  ×1     10^9  ×1     10^2   ×1
```

**偏偏是这两种**——文档讲「范围 / 上限」用的就是它们。
**`2^48` = 281,474,976,710,656，拍平后写成 `248`。丢一个上标，从 2.8×10¹⁴ 变成 248。**

## 三、为什么十五类检查一条都看不见它

**因为语料就是基准。** 所有检查做的是「wiki ↔ 语料」比对。
**语料自己错了，一个忠实的 wiki 页在每一类检查下都是绿的。**

- 第六类查 frontmatter 字段**在不在** → 与数字无关
- 第七类查 wiki 引文与语料**逐字相同** → **语料错，页也跟着错，于是「相同」，判过**
- 第十四类查 `index.md` 的自我声明 → 无关

> **这是「检查比它自称的范围窄」的第 N 次，但形状是新的：**
> 前几次是**检查的范围**没盖住，这一次是**基准本身**有问题——
> **再宽的检查也抓不到，因为尺子本身是弯的。**

## 五、`<sub>` 的对照——**为什么不构成同类问题**

| 标签 | 总数 | 拍平后果 |
|---|---|---|
| `<sup>` | 1,699 | **换了个数**（`2^48`→`248`）——**真错** |
| `<sub>` | 1,031 | `V_GS`→`VGS`——**这正是它平时的写法**，不算错 |

**上下标的后果不对称。** 下标拍平基本无害（全库 1,031 处只丢 1 处，且是 `f<sub>MAXφ</sub>` 这种希腊字母角标），
**上标拍平只要内容是数字就致命**。**这也解释了为什么这一类错能潜伏这么久**——
抽查时看到 `<sub>` 没事，很容易顺推 `<sup>` 也没事。

## 七、复核办法

```bash
cd F:\master-dev\dorm-wsl-sytest\tdc-html
python -X utf8 - <<'PY'
import re, pathlib, html
MD=pathlib.Path('agent-markdown/by-category'); HT=pathlib.Path('raw')
stem2md={}
for p in MD.rglob('*.md'):
    m=re.search(r'^source_topic:\s*["\']?([^"\'\s]+)', p.read_bytes().decode('utf-8','replace'), re.M)
    if m: stem2md.setdefault(m.group(1).replace('.htm','').replace('.html',''),[]).append(p)
body=re.compile(r'<body\b[^>]*>(.*)</body\s*>',re.I|re.S); plain=re.compile(r'<[^>]+>')
sup=re.compile(r'<sup\b[^>]*>(\d{1,3})</sup\s*>',re.I|re.S)
tot=bad=0
for f in sorted(HT.glob('*.htm'))+sorted(HT.glob('*.html')):
    raw=f.read_bytes()
    try: t=raw.decode('utf-8')
    except: t=raw.decode('cp1252','replace')
    m=body.search(t); seg=m.group(1) if m else t
    for mm in sup.finditer(seg):
        before=html.unescape(plain.sub('',seg[max(0,mm.start()-6):mm.start()])).rstrip()
        if not before or not before[-1].isdigit(): continue
        tot+=1
        lit=f'{before[-1]}{mm.group(1)}'
        for md in stem2md.get(f.stem,[]):
            if lit in md.read_bytes().decode('utf-8','replace'): bad+=1; break
print(f'数字上标贴数字: {tot} 处；被拍平: {bad} 处')
PY
```

**改之前**预期输出：`数字上标贴数字: 151 处；被拍平: 151 处`。若两个数不等或总数变了，说明语料被换过。

> ⚠️ **改完之后，上面这段脚本的「被拍平」数不再是有意义的判据。**
> 它用的是最朴素的 `lit in md`——`27` / `25` / `07` 这种两位串**在文档里本来就可能自然出现**
> （图号、pogo block、`1+X6+X7 127` 之类），修完仍会报出二十几处**假阳性**。
> **改后真正的判据是「逐字节重放」，不是任何计数**（两条都在下面 §八）：
> - 语料侧：把那 60 篇换回 `HEAD` 版重跑修复脚本 → 应得 **151 处 / 60 篇**，
>   且改动结果与工作区**逐字节相同**；
> - 行级：`git diff` 里每一处改动**必须只是插入了一个 `^N`**，不得有别的字符变化。
>
> **先前写在这里的判据是错的，已删。** 原本写「`fix_corpus_superscript.py` 空跑
> → 应报 `已定位 151 / 未定位 0`」——**修完之后恰恰相反**：那个定位器找的是
> 「粘连的字面量」，而粘连形态已经被改掉了，所以它必然报 `已定位 0 / 未定位 151`。
> 我照旧值去核，看到 0 差点当成「一处都没动」。
> **判据和它要判的对象一起变了，计数就不再是判据。**
>
> 顺带一句：这个空跑**还会写出空产物**（写盘语句在 `--apply` 判断之前）。
> 2026-09-22 就是这一步把 `_assign.json` 和证据表**覆盖成空**的。
> 现已加互锁——**空结果不许覆盖非空清单**，见 §十·错三。
>
> wiki 侧判据不变：`extract/fix_wiki_superscript.py` 空跑 → 应报 `对证成立 0 处`。

## 十、**我犯的三个错，以及一次被工具当场纠正**

错一、错二在 **wiki 层**；错三在**语料层**，是脚本 bug，跟 A 类判据无关，

### 错一（老毛病，第二次犯）：关键词过滤 → 漏

第一次改 wiki，我用「幂语境关键词」（`range of` / `between 0 and` / `maximum value` …）
当过滤器筛候选。筛出 **49 处**，改了。

换成对证判据后，候选变成 **91 处**。漏掉的 42 处，语料里明明是同一个说法，
**只是换了个介词**：

```
between 0 and 248     ← 我盖住了
range 0 to 248        ← 漏了（"range 0 to"，不是 "range of"）
range for this parameter is 0 to 248   ← 漏了（"range for"）
between 1 and 216-1   ← 漏了（"between 1 and"，不是 "between 0 and"）
it's 23 = 8 possible states            ← 漏了
```

> **「检查比它自称的范围窄」的第 N+1 次，我自己犯的。**
> 关键词过滤的毛病：**它把「我没想到的写法」判成没问题，而且不报错。**

### 错二（新形状）：对证判据 → **串**

换成对证判据（把候选改成 `2^N`、去修好的语料里搜）之后，91 处里
**88 处落在页面的 `<!-- 语法节 begin/end -->` 里**——**那是脚本写的一节**（§4）。
我把它们全改了。**其中 2 处是误改。**

**为什么误**：`command-reference` 的语法节里那句话，
**在语料里有 6 篇文档写着同一句**：

| 源 HTML | 原文 |
|---|---|
| `98873.htm` / `98873_2` / `98581` / `98581_2` | `0 and 2<sup>48</sup>` |
| `98874.htm` / `98874_2` | `0 and 248`（**HTML 里就没有 `<sup>`**） |

**对证判据只问「这句话在语料里有没有 `2^48` 的样子」，没问「这句话是从哪一篇来的」。**
6 篇共用一句雷同的话，它就串了——把那 2 处上游本来就写 `248` 的也"修"了。

> **判据的第三处盲区**：① 关键词过滤漏「没想到的写法」；
> ② 对证判据**分不出「引用」和「断言」**（见下面的具名例外）；
> ③ 对证判据**分不出「这句话是从哪一篇来的」**。

不是「我知道它没问题」，是「每次运行都验一遍」。

| 写盘在 `--apply` 之前 | 改完语料后又跑了一次空跑 |
| 产物未追踪、不可回滚 | 一直没给它俩留版本 |

**重算回来了**（不是从记忆里补写的）：修复脚本的输入是
`(raw 的 HTML, agent-markdown 的 md)`，**HTML 从未改动**；
把那 60 篇 md 的读取换成 **`git show HEAD:<path>` 的版本**（即修复前），
跑出来的就是当初那 151 处。配方（**不存脚本，存方法**）：

```bash
# 1. 那 60 篇的名单——就是语料里改过的那批（HTML 必须为空）
git -C F:/master-dev/dorm-wsl-sytest diff --name-only     # 只应有 tdc-html/agent-markdown/…

# 2. 把 fix_corpus_superscript.py 的 rd() 改成：先查 _HEAD，命中就读它
#    （补丁要打在**源码**上，不能只改 exec 后的命名空间——
#     模块体里的 `def rd` 会把它覆盖回去）
#    _HEAD[路径] = subprocess.run(['git','-C',…,'show',f'HEAD:{rel}']).stdout
#    其余文件照读工作区；路径仍写回真语料路径。空跑即可。
```

> **别把这段做成常驻脚本**：它成立的前提是「改动尚未提交」，
> 提交之后 `git diff --name-only` 返回空，脚本就废了，而**废掉的脚本比没有脚本更危险**——
> 它会以「跑通了但结果不对」的样子骗人。**方法留在这里，够重放。**

**为什么这个前提这么值钱**：HTML 一个字没动，所以「修复前」永远是**可再生的**。
这本身就是 §1.2 那条规矩（**只改 markdown，HTML 不动**）的第二个用处——
第一个用处是对证（HTML 是唯一上游），**第二个是重放**。

**独立交叉验证**：被毁的证据表里，**「## 未定位（未改）」那一节把 151 条
完整保留了下来**（只丢了偏移，`md 文件名 — base^exp（源 HTML）` 三元组还在）。
重算结果与它**逐条比对：151 条 / 91 种三元组，零差异**——
**两份产物分别独立重算，对上了。**

**顺带查明的一件事**：`git archive HEAD tdc-html/agent-markdown` 导出的树
**与工作区篇数对不上**（9,400 vs 9,400，但少至少一篇
`03.03.05.06.03_Test_Method_API_for_Executing_a_Non-Blocking_Digital_Capture_Test.md`）。
所以**没有走整树导出**，改成按 `git diff --name-only` **精确取那 60 篇**——
**只碰需要碰的，副作用最小**。

**修法（堵的是这一类，不是这一次）**：加互锁 `guard()`——
**空结果不许覆盖非空清单**。没有把写盘挪进 `--apply`，因为那会把
「空跑可核对」这个用处砍掉；拦的只是「空表盖好表」。

**验证**：拿**已修好的**语料空跑（正是当初毁掉清单的那一步）——
拦截生效，两份产物 `sha256` 一字未动：

```
f1042b29e56e6171…  _assign.json                        （50,075 字节的产物守住了）
dd17495192aadacc…  findings-corpus-superscript-loss-evidence.md
```

> **一句话**：判据会说谎（错一、错二），**工具会说谎**（错三：空跑本该只读）。
> 能兜住的只有两样——**证据留在上游**（HTML 没动，才重算得出来），
> **产物进版本库**（没做到，这次是靠重算救的，下次未必有材料）。

## 十二、A 类判据的边界，被一个真实案例检验了：**同一句话，原厂 HTML 自己两个说法**

定位 `command-reference` 那 2 处误改时翻出来的。同一句参数说明：

```
In the Start Analysis mode, enter a positive value between 0 and ...
```

**在 6 篇文档里逐字相同，而源 HTML 的写法分两派：**

| 源 HTML | 原文 | 篇数 |
|---|---|---|
| `98873.htm` / `98873_2.htm` / `98581.htm` / `98581_2.htm` | `0 and 2<sup>48</sup>` | 4 |
| `98874.htm` / `98874_2.htm` | `0 and 248` | 2 |

**这不是转换损坏，是原厂文档自己不一致。**
（`2^48` 才讲得通——「Start Analysis」的计数范围是 2⁴⁸；`248` 讲不通。）

**按 §1.2 的判据办：**

- A 类第 1 条要求「**有上游可对证**——`tdc-html/raw/` 里找得到对应 HTML，**且明写着原意**」。
  这里上游**两个说法**，**对不出唯一原意** → **不成立**。
- 于是它归 **B 类「文档内容本身有误」→ 一个字不许动**，只能在 wiki 层标注。

**语料修复脚本没改那两篇——是对的。** 它只跟 `<sup>` 走；
`98874.htm` 没有 `<sup>`，所以没动。**这是判据按设计工作，不是漏。**

> **这条值得单记，因为它是 A 类规矩立起来之后第一次被真实案例顶到边界上。**
> **边界扛住了**——而且扛住的方式是「判据自动不动手」，不是「我记得别动」。
> **两条待办**（不在本批）：
> ① wiki 层该给这两处加标注（说明上游两个说法）；
> ② 这类「同一句在多篇里不一致」的形态，值得像 §11.2 那样单列一族去扫一遍。
