# 施工单：把**全库表格**换成「指针」（**还没动手**）

> **这份文档是给一个全新的会话看的。** 它自带全部背景 —— 不要假设读者知道之前发生过什么。
> 写于 2026-10-10。**一个字都还没改。**

---

## 一、要干什么

前面七批把**能修的**表都修了（4,748 张），修不了的挂了路牌（1,842 张）。

**这一批换思路：不再区分「能修 / 不能修」—— 全库表格一律从 markdown 拿掉，只留一句指针。**

**理由：markdown 表达表格是有损的，而失败模式最坏 ——「看起来对，其实是错的」。**
表示不了的那部分（合并格、嵌套表、格内块级内容）**没法在 markdown 里标出来**，
读的人分不出「简单表」和「被压扁的复杂表」。而规格文档的电压范围、电流上限就在这些表里。

## 三、指针块的形态（★ 定稿）

```
> ⚠️ 表格指针（非原文）：本表 markdown 表达不了。真表见 `tdc-html/raw/351256.htm`
> 第 4 张有格子的 `<table>`（跳过 `<table id="vr">` 空壳）：8 行 × 3 列，含 rowspan。
> 首行（上游原文）：Single-ended impedance | -1.5 V ≤ V_SE ≤ 3.0 V | 50 Ω ± 3 Ω
> 表内引用（8 条，供检索）：[DFUP](<…>) · [SQST](<…>) · …
```

**四条硬要求：**

1. **固定措辞 + 自我声明「非原文」+ 指确切文件** —— `schema.md` **§1.3**，与「合并格的转录说明」同源。
2. **描述只放两类**：**结构**（`R 行 × C 列`、有无 rowspan/colspan/嵌套，从上游数，是事实）
   + **上游首行原文**（照抄，不转述）。
3. **★ 不许出现任何自撰的内容话术。**
   > 反例：格子里是 `-1.5 V 鈮?VSE 鈮?3.0 V`，模型摘要会写成「输入电压范围 -1.5 V 至 3.0 V」——
   > **把一处显性损坏洗成通顺、看似权威的散文，比不改更坏。**
   > §1.3：「只描述做过什么 + 指出真结构在哪，不宣称一条能反推结构的规矩。」
4. **表内引用要保下来**（§七①），作为第 4 行，也是搜索命中的主要来源。

**细则**：首行含 `|`（实测有 `4 | 8`）要转义；首行是合并格标注；首行为空退到第 2 行并写明；
引用超 N 条（建议 20）折叠成计数；**引用文字含残留乱码则照抄**（§11.2），本批不越界改（§1.2）。

## 四、怎么保证「全找得到」（★ 成立前提）

### 4.1 从 md 侧，保证不了

**压平后的表在 md 里没有任何标记** —— 它就是「一段普通文字 + 若干行首带 ` | ` 的行」，
没有任何办法把「压平的表」和「正文里正好有竖线开头」分开。

**第七批已实测过这个漏**（`wiki/log.md`）：

> ① **漏了一整个子形态** —— 表格的行短到能挤在一行时（` | Force Voltage | 1 | 1 mV |`），
> 压平后**一行孤立竖线都不产生**，整类落在候选集外。

换了口径补回 744 张，同时暴露第二个盲区（**对已修文档是盲的**，A5 修过的 3,642 条所在文档 100% 被跳过）。
**换口径只是换一个盲区，不是消灭盲区。**

### 4.2 所以反过来：**不在 md 里找表，在上游数表**

上游 `<table>` 是**封闭可数集**。每一张都必须落到 `{ 已定位 , 有理由的例外 }`。
**找不到 = 大声报错，不是静默跳过** —— 「漏」从**静默**变成**有声**。

### 4.3 ★ 但「什么算一张表」的定义必须先钉死

### 4.3 `<table>` 分类 —— ✅ **2026-10-10 已完成，规则经人确认**

```
上游 <table> 共 16,289
  ├─ 空壳      9,398   没格子，或去标签后 < 3 字符        → 跳过
  └─ 内容表    6,891   → 要指针化
        ├─ .htm    6,593   ← 台账（6,590 条）覆盖的就是这些
        └─ .html     298   ← ★ 从来没进过任何清单
```

空壳构成：`id="vr"` 9,320 + `id="pageHeader"` 27 + 其余无内容 51。

**判据（人已认）**：**有 `<td>`/`<th>` 格子，且去掉标签后 ≥ 3 个字符 → 内容表，否则空壳。**

**核的方式**：按 `(id, class)` 分桶 + 按 `(行数, 格子数)` 分布 + **逐桶抽样打开看**
（`class="ly"`、无属性那 717 个、各 `frame-*` 都看了）。
**没做的**：没有 16,289 个逐个打开；**阈值「3 字符」是拍的**。

**★ 这一步推翻了两个旧说法：**

1. **`class="ly"` 不是「排版壳」** —— 1,562 个里 **1,560 个有内容**（`<caption>`/`<colgroup>`/`<tbody>` 俱全）。
   A6 记的「103 张纯排版壳」是 **`class=ly` + 1 行 + 包着嵌套表** 的**交集**，不是这一类的全部。
   → **照旧说法排除，会一口气漏掉 1,500 多张真表。**
2. **298 张表从来没进过任何清单** —— 这才是「台账 6,590 vs 上游 6,596」那个差数的**真正来历**
   （不是 6 张，是 298 张；见 §2.4），其中 **95 张是正经的 V93000 SOC Release Notes**。

**定义错的方向不一样，后果不对称：**

| | 后果 | 能发现吗 |
|---|---|---|
| **宽了** | 把空壳也指针化，灌进一批噪音 | 看得见 |
| **窄了** | **漏掉一整类真表** | **发现不了** —— 账是从上游数的，**账还是平的** |

**遗留小尾巴**：无 `class` 无 `id` 那 717 个里，有 **48 个是空的**（不是 `id="vr"`，是别的 chrome），
要单独看一眼确认。

### 4.4 今天已知的盲区

```
上游有内容表、md 侧毫无表痕迹      15 篇（按早期口径量，需按 §2.4 重算）
台账 6,590 vs 上游 6,596            差 6 张
md 标准表块 5,218 vs 台账 4,748     差 ~470 个块
```

**都是有限的、能一张一张点名的。**

### 4.5 这里的「100%」是什么意思

**是「账目闭合」，不是「扫描无遗漏」。** 三条必须同时成立：

1. **上游 → md**：每张上游内容表都能指到一处 md 区域，**或落到有理由的例外清单**
2. **md → 上游**：md 里每处表形态都能反查到上游某张表
3. **例外清单必须人工过完** —— 数量必须小到能一张张看（**几十张量级**）

**做不到的承诺**：一个「我把 md 扫了一遍，全找到了」的保证。本项目**已经栽过两次**这种假承诺：

> 我曾拿「工具再跑 = 0 可修」当作「做完了」的证据 —— **不成立**。
> 那个 0 是**看不见**。**判据报的 0，只有在候选口径本身可信时才说明问题。**

## 五、定位算法（主 + 兜底）

### 5.1 ★ 清单里的 `a`/`e` 偏移**不能用来写入**

`a`/`e` 是**绝对字符位置**，只在「从此文件开头到那里一个字没变过」时有效。
而语料被改了八批，每批都在改**长度**（乱码修复变短、表格修复大减 18 万行、路牌插入变长）。

**实测（抽 500 条）**：

```
那段文字还在文件里吗   500 / 500   ← 在
还在原来的位置吗         3 / 500   ← 不在
平移量                 平均 +91，范围 −1,250 ～ +3,932
```

**危险实例**（`02.03.03.01_DUT_interface_layout.md`）：清单记第 7,223 字符，
实际在 9,193。**按 `a` 取出来是普通正文，照它写会删掉正文、把表留下。**

> **分清**：偏移对「**重放**」有用（拿当时的基线 + 偏移能复原那次改动，§八）；
> 对「**在今天的文件上动手**」没用。两件事别混。

### 5.2 主锚：表自身的文字（`new` 字段）

清单里存了**那段文字本身**。实测 **`s.find(new)` 500/500 命中**。→ **用文字定位。**

**约束**：① **唯一命中**（出现 ≥2 次就跳过，A5/A7 验证过的规矩）；
② 命中处必须落在该文件的表格形态区域；③ 整块区域一起替换。

### 5.3 兜底锚：表前那段散文（第八批已跑过 1,845 次）

上游每张表前面总有段文字，那文字在 md 里也在 → 拿它定位 → 表就在它下面。

**四条约束，缺一不可：**

1. **锚必须是纯 ASCII** —— 夹着 `≤`、`°` 的地方锚本身可能就是坏的。
   （A1 第二批第一次试「开窗找锚」成功率只有 **40%**，第一条原因就是这个。）
2. **锚必须整篇唯一** —— `MEMORY_EMULATION` 那张就栽在这：**整节内容重复了一遍**。
3. **比对前必须归一化** —— 去标签 + 解实体 + 抹空白。**复用 `fix_corpus_tables.py` 的 `norm_up()`，
   不要另写一份**（§11.5「同一个东西两个数」）。
4. **上游侧「先定位文字，再往后找 `<table>`」** —— 锚是文字、表是标签。

**★ 这是兜底，不是万能钥匙**：① **A6 嵌套表** —— 上游是 `<td>` 里套 `<table>`，
「表前那段散文」本身就在另一张表里面；② 转换器**拍平块级元素**时会把 `<div>` 边界吃掉，
散文末尾可能已被咬掉一角。

**兜底失败的处置：整张不动，报出来**，进 §四.5 的例外清单。

## 六、分批与自查（★）

**每完成一批就停下来查这一批。** 这不是新规矩——你们每批本来就一个 commit、一次重放——
只是把频率提高到 100 张一次。

### 四项检查

| | 查什么 | 谁做 |
|---|---|---|
| **①** | **逐字节重放** —— `git show HEAD:` + 清单偏移，能否一字不差复现这 100 处 | 脚本 |
| **②** | **残留归零** —— 这 100 张所在文件里，再也扫不出表形态 | 脚本 |
| **③** | **★ 指针自己写的话对不对** —— 「第 4 张表、8 行 3 列、首行是 XXX」**回上游逐项核对** | 脚本 |
| **④** | **肉眼抽看** —— 抽 8~10 处，看替换干不干净、上下文有没有被咬掉 | 模型，有问题再叫人 |

### ★ ③ 是新增的，也是最该加的一条

指针块里每一句都是**断言**：`第 4 张有格子的 <table>` / `8 行 × 3 列` / `首行：…`。
**这些话是脚本从上游算出来的，算错了没人知道 —— 而它又最好核。**

**以前的批次都没有这道。** 加进去之后，「指针内容本身对不对」才有人管。

### 节奏

```
①②③   每 100 张自动跑     ← 便宜，几秒
④      每 100 张抽 8 处      ← 模型看
```

**批次按「难度类」切，不按纯计数切：**

- 简单表（2 列、无合并格）—— 错误率极低，抽看可以稀
- **合并格 / 嵌套表 / 兜底锚定位的 / 乱码格子所在的** —— **每批都要严看**

不同难度错误率差着量级，同一频率对待是浪费。

### 唯一的停止条件

**①②③ 任一项不平 → 立刻停。** 那说明工具本身有系统性错误，后面几千张全是白做。
**没触发，就一路走下去。**

## 八、流程（照 `schema.md` §1.2 / §1.3）

1. **空跑** → 出 `extract/_assign_tabledel.json` + 证据表
   （每张：md、topic、tbl、R×C、**被替换区域的 sha1**、主锚还是兜底锚）
2. **摆证据 → 人批准** → **只改被批准的那几处**
3. `--apply`（**按 §六 分批**）
4. **逐字节重放验证** —— 这一批的 **base commit**（不是 `HEAD`，见下）+ 偏移，
   必须与工作区逐字节相同
   > ⚠️ 语料仓 **`core.autocrlf=true`**（git 存 LF、工作区 CRLF）。
   > **重放必须先对齐换行**，否则 **100% 误报** —— A5 时第一跑就栽在这。
   > **写清单时必须同时记下换行口径。**
5. **记 `wiki/log.md`**
6. **重跑五步 + 十五类闸门**

**纪律三条（§1.2 明文）**：❌ 不许「顺手」改旁边 ｜ ❌ 不许把一次批准当永久授权 ｜ ❌ 不许改完不记

> **`_assign_tabledel.json` 与证据表必须入库。** 血换来的：2026-09-22，那两份当时是**未追踪文件**，
> 一次空跑用空表盖掉了好清单，**git 救不回**。「数据要能重算」不能代替留版本。

### 版本库怎么进（★）

**不进主线。按类开分支，`--no-ff` 合回。**

| | |
|---|---|
| 分支 | **按类开**：`table-to-pointer/repaired`、`/pointer-marked`、`/doxygen`（主线只多 3 个 merge 点） |
| 分支上的 commit | **每 100 张一条**（§六 的检查过了就 commit） |
| 合回主线 | **`git merge --no-ff`** |
| 分支 | **保留，不删** —— 它就是那几十个细 commit 的家 |

- 图上看到的是**一条伸出去、再合回来的支线**，主线不会多塞 60 个 commit。
- **不许 squash** —— 那会把支线整个抹掉、只剩主线一个点，逐批回滚的粒度也没了。
- **必须写 `--no-ff`** —— 普通的 `git merge` 在主线没动过时会 fast-forward，
  支线直接贴到主线上，**连 merge 点都不产生**。
- （知道一下：`--no-ff` 之后那几十个 commit 仍是主线的祖先，`git log` 会列出来；
  只看主线用 `git log --first-parent`。不影响读图。）

**两个仓都要**：语料仓 `tdc-html` + 工具仓 `understand-anything-wiki`，各开分支、各 `--no-ff` 合回、互相记 commit 号。

**每批清单必须记 `base_commit` / `head_commit`** —— 因为分支上的 `HEAD` 每个 commit 都在动，
不记就没法以后定位「第 17 批改的是哪一段」，§八 第 4 步的重放也就无从复现。
