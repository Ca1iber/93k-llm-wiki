## 归类

按本工程的对账规矩，这是 **(b) 基线工具不精确**——**但锅在规格，不在脚本**：

链接照建 → 第八类照红。**规则本身在制造它要防的那件事。**

### 95 / 16，不是 41 / 71

本文那张「有同名定义文档 41 / 是某文档标题的子串 71」的分法**不成立**。
「子串」这个判据太粗，而且**没做归一化**，于是把两类东西混成了一类：

| | 数 | 是什么 |
|---|---|---|
| ① **自己就有文档** | **95** | 真对象。几乎全是 `02.06.02.02.*` 的命令（`PSLV` `DRLV` `RCLV` `WSUS` `JDST` …），另有 GUI 视图 / 工具 / 文件 |
| ② 只是别人标题里的一段 | **16** | `ps1600` ⊂ `PS1600_overview`、`technology-file` ⊂ `Technology file for a device` |

**两个错在哪**：

- `pslv` 被判成「子串」——可它的文档标题就是 `PSLV, PSLV? - (Power Supply LeVel)`，
  **它自己就是那篇文档定义的对象**，不是谁的别名。按标题头那串命令名判（`title_aliases`，
  2026-09-24 修语法节时加的那个判据）就归到 ①。
- `table-filter` 也被判成「子串」——它的文档标题是 `Table filter`（**空格**），
  而 slug 写的是连字符。**判据没做归一化**，于是两个明明是同一个名字的东西对不上。

**归一化只留 `[a-z0-9]` 之后**，95 / 16。

### 剩下两件事，都要人定 —— `一个字没动`

**② 那 16 个里，9 个的覆盖文档已经有页，7 个没有。** 有页的那 9 个
